# v0.10.4 Raven icon separation

Goal: keep real boat docks visually native while Completionist Ravens use their own map/compass artwork, then scale the proven native marker/navigation path to all remaining Ravens.

## Field-proven baseline

`feat/v0.10.3-native-raven` proves a dedicated authored Raven token can be loaded from `mapmaster.dcb` + `mapcoords.dcb` + `compassgraph.dcb` and safely tracked with `game.Compass.ShowMarker`/`HideMarker`. Native distance/routing works and the old R3/L3 surrogate is not needed for Raven tracking.

## Current visual coupling to remove

The Raven proof currently inherits DockPoint identity in two places:

1. authored marker template/icon/flag: `goMapIconDock` + `DockPoint`;
2. v0.10.2 texture proof globally overrides the DockPoint map textures.

That makes DockPoint a useful proof carrier but not a production Raven identity. A production Raven marker must not change the artwork of real boat docks.

## Required separation

- Preserve stock DockPoint map and compass artwork for real docks.
- Give Completionist Raven map pins the existing user-authored Raven artwork.
- Give Raven compass targets a Raven-specific visual identity without replacing any stock class globally.
- Keep native marker coordinates/graph routing and `InitState=0` semantics.
- Never change the Kratos/Omega marker.

## Preferred implementation order

1. Find whether a distinct per-instance map material/material-swap path exists for `Map.CreateMarkerIcon` output.
2. Identify the authored `CompassIconClass` data source and determine whether a new Completionist-only class can be added safely by DCB patching.
3. If custom class authoring is viable, use a dedicated name such as `CompletionistRaven` and bind only the Completionist Raven texture/material to it.
4. If custom class authoring is not viable, use a dedicated UI carrier/material swap that is not used by stock markers. Do not accept a global override of another stock marker class as the finished solution.
5. Once Raven-vs-Dock visual separation is proven, generate one independent native token/coordinate/graph attachment per remaining Raven and map synthetic selections to the matching native ID.

## Multi-Raven invariants

Each Raven must have:

- deterministic unique Completionist marker name/hash;
- its own world coordinate/WAD/region association;
- a verified graph attachment;
- its own completion state observation;
- Add/Remove/Replace tracking that owns only that Raven ID;
- automatic native HideMarker when that Raven is killed/already killed;
- no artificial `Map.ChangeMarkerState` or save/progression writes.

Do not expand to Nornir or other collectible types until all Ravens are visually and behaviourally correct.
