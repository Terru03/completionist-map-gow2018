## Restart / rollback clarification

The successful collector intentionally runs full rollback after archiving the proof. It restores the stock DCB files and removes the v0.10.3 Lua show probe. Therefore reopening the game after a successful collector run returns to the pre-proof v0.10.1/v0.10.2 environment, where the old `R3_L3`/keyboard-equivalent surrogate can appear again. That does **not** invalidate the successful native proof.

The proof itself also declares `calls_on_load=false`: it never reissues `Compass.ShowMarker` merely because the game starts. A later session needs the authored marker data loaded and an explicit tracking request, or a future production tracking-state restore mechanism.

The successful proof is preserved in `archive/field-logs/completionist-v103-native-compass-show.txt` and original commit `2e7a0cc68e8b5796f066a79988ea860bdaaf9622`.

## Engineering conclusion

The final Completionist architecture can now use:

1. dedicated authored native marker records at collectible positions;
2. Completionist synthetic/custom-art map selection;
3. selection mapped to the corresponding native marker ID;
4. `game.Compass.ShowMarker` / `HideMarker` for game-owned HUD compass placement, distance and route behaviour;
5. collectible lifecycle events to clear the owned native marker when completed.

The old direct-XYZ `R3_L3` HUD carrier is no longer required as the final compass implementation and should be removed/disabled in production builds.

Remaining work includes productionising marker generation for all collectible categories, defining non-conflicting custom compass artwork/class behaviour, deciding whether Completionist tracking should persist across process restarts, and validating route behaviour around graph turns/gateways plus stock-marker regressions.
