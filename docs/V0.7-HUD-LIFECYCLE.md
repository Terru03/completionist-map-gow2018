# v0.7 custom HUD and collectible lifecycle

## v0.7.7 confirmed end-to-end target accuracy

The known remaining Veithurgard Raven at:

```text
x=-64.850898742676
y=12.987384796143
z=787.30694580078
```

was successfully represented by the custom map pin and the HUD-native compass proof marker.

User validation confirmed:

- the map marker pointed to the correct remaining Raven;
- the custom compass bearing led to the real Raven;
- the Raven was found and killed;
- the HUD-native borrowed `R3_L3` object rendered and moved correctly on the gameplay compass.

Runtime logs showed the borrowed object moving from its original HUD position to the compass strip and tracking changing signed bearing. This confirms the arbitrary world-XYZ -> gameplay HUD compass path.

## Remaining v0.7.7 bug

After the Raven was killed, the custom target remained active. The map/HUD prototype only tracked its own `active` toggle and had no connection to the collectible's persisted completion state.

## v0.7.8 lifecycle fix

`precisionchallenge.lua` already owns the authoritative per-Raven state:

```lua
local ravenKilled = false
```

and persists it through `OnSaveCheckpoint` / `OnRestoreCheckpoint`.

v0.7.8 adds a read-only lifecycle bridge for the exact Veithurgard test Raven. It publishes that existing state to the Completionist Map prototype from:

- `OnRestoreCheckpoint`
- `OnStart`
- `OnHitByWeapon`

The bridge does not modify `ravenKilled`, quest counters, region-summary progress, or save data.

When the target Raven is observed as killed:

1. custom compass `active` is forced false;
2. the borrowed HUD visual is restored/hidden;
3. an existing custom map pin is destroyed;
4. future map opens skip pin creation;
5. Add/Remove from Compass is no longer offered.

A secondary fallback checks whether `RegionSummary_VF_Raven_Parent` is `Complete`, which is useful if Veithurgard's Raven WAD is not currently streamed.

## General architecture consequence

This is the correct pattern for the final mod:

```text
catalogue entry
  -> world XYZ + collectible type + region summary link

collectible gameplay script / restored save state
  -> authoritative completed vs remaining state

remaining entry
  -> custom map pin
  -> custom HUD-native compass indicator

completion event
  -> immediately remove map/HUD representation
```

For Ravens specifically, the eventual generic implementation should maintain a coordinate-keyed runtime registry populated by `precisionchallenge.lua`, rather than hard-coding only one Raven.

## Safety

The v0.7.8 path does not use:

- `game.Compass.ShowMarker()` for synthetic targets;
- `Map.ChangeMarkerState()`;
- hidden stock marker IDs;
- quest progress mutation;
- synthetic save state.
