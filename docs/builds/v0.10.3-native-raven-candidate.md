# Completionist Map v0.10.3 native Raven candidate

Status: **FIELD TEST CANDIDATE**. Raven-only. Do not merge until route/lifecycle/regression tests pass.

## Architecture

The Veithurgard Raven keeps the existing Completionist synthetic/custom-art map selection, but Add to Compass no longer activates the direct-XYZ `R3_L3` HUD surrogate.

Instead it maps to the independently-authored native token:

- name: `Completionist_V103_Veithurgard_Raven_01`
- ID: `E15E6BC82AE2773E`
- authored position: `(-64.875, 12.984375, 787.5)`
- native class used for the current proof/candidate: `DockPoint`

The three validated DCB copies provide the marker record, coordinate record and compass graph edge. `game.Compass.ShowMarker` / `HideMarker` then own compass presentation, native distance and routing behaviour.

The native token remains `InitState=0`; this candidate does not call `Map.ChangeMarkerState` or write artificial progression state.

## Raven-only behaviour

- Completionist Raven Add/Remove/Replace in Compass uses the dedicated native marker.
- Any old `CompletionistMapV100Target` Raven state is forced inactive while the native Raven target is being tracked, preventing the legacy `R3_L3` carrier from appearing for Raven.
- Killing/restoring the exact Veithurgard target Raven hides only `Completionist_V103_Veithurgard_Raven_01`.
- Stock compass targets are hidden only when the user chooses Raven and the UI is performing normal Replace in Compass semantics.
- Stock marker records and the native Kratos/Omega marker are not mutated.
- Nornir still uses the previous prototype path in this candidate; migration is intentionally deferred until Raven passes field validation.

## Persistence

The authored DCB files and Lua bridge remain installed across process restarts until explicit uninstall. Native compass tracking itself is intentionally **not** auto-restored on process start yet. After restarting God of War, select the Raven and Add to Compass again.

## Install

From repository root, on branch `feat/v0.10.3-native-raven`, with God of War closed:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
    -File ".\tools\v0.10.3\install-native-raven-candidate.ps1" `
    -Mode Install
```

The installer validates the researched `GoW.exe`, validates all three stock DCB hashes, builds the Raven copies outside the game directory, backs up the original DCBs and Lua overrides, then installs the candidate. It never calls `ShowMarker` during installation.

## Field validation

1. Launch God of War and load the Veithurgard save.
2. Open Midgard map and select the Completionist Raven.
3. Press Add to Compass once.
4. Confirm the HUD uses the real native marker/distance and no L3/R3 keyboard prompt surrogate appears.
5. Walk far enough away and around solid geometry / a route turn that a straight bearing to the Raven would differ from a route-aware direction. Capture a screenshot where the distinction is visible if possible.
6. Reopen the map and verify Remove from Compass and Add again.
7. Optionally replace Raven with a normal stock marker, then track Raven again; neither marker should be permanently changed.
8. If practical on a disposable/current test state, kill the target Raven and verify the native marker disappears immediately and does not return.
9. Fully close the game.
10. Collect the log without uninstalling:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
    -File ".\tools\v0.10.3\collect-native-raven-candidate.ps1"
```

## Rollback

With God of War closed:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
    -File ".\tools\v0.10.3\install-native-raven-candidate.ps1" `
    -Mode Remove
```

Rollback restores the pre-candidate `mapmenu.lua`, `precisionchallenge.lua`, and all three researched stock DCB files byte-for-byte. It refuses to overwrite a file that was independently changed after candidate installation.
