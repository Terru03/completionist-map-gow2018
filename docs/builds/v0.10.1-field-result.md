# v0.10.1 field result

Test target: Midgard / Veithurgard

## Installation

The self-contained local-icons package installed successfully. All ten bundled concept PNG masters were validated and 24/32/48/64 px candidates were generated without GitHub authentication or private raw downloads.

## Runtime result

The custom Raven, Nornir Chest and Nornir Seal markers still rendered as their borrowed DockPoint/boat visual.

The capability log explains why:

- `SetTexture=false`
- `SetTextureName=false`
- `SetImage=false`
- `SetImagePath=false`
- `SetSprite=false`
- `SetMaterialSwap=true`

The same direct image setters were unavailable through the probed `game.UI` path.

Consequently v0.10.1 correctly emitted `ICON_BIND_RESULT ... direct=false fallback=DockPointProxy` for Raven, Nornir Chest and Nornir Seal.

## Behaviour regression result

The tested behavioural path remained healthy:

- Raven pin created at the expected map coordinate.
- Nornir parent and two remaining Breakable seals were created independently.
- Distinct backing IDs prevented marker aliasing.
- Native collision selection worked with camera snapping disabled.
- Raven and Nornir direct-XYZ compass tracking both toggled.
- Hide/Show Kratos worked.
- The Kratos player marker remained the native Omega symbol.

## Player marker invariant

The native Kratos/Omega map marker is now a hard project invariant. Completionist Map may hide or show it, but must not replace its artwork or material. The `player_marker` concept master is reference-only.

## Next rendering route

Loose PNG binding is now ruled out for the currently exposed synthetic map objects.

The next prototype should investigate authored material/MPIcon integration rather than attempting more `SetTexture`/`SetImage` variants.

A strong lead exists in the exposed game Lua library `ui/mpicon.lua`: it provides `mpicon.level.SetMaterialSwap(go, iconName, materialSwapName)`, which forwards to `game.UI.SetMPIconMaterialSwap` when that engine function exists.

The next test should therefore determine:

1. whether the borrowed map icon is addressable as an MPIcon and which `iconName` it uses;
2. whether `game.UI.SetMPIconMaterialSwap` is exposed at runtime;
3. which authored material-swap names are valid for the DockPoint/map icon family;
4. whether a custom texture can be introduced through the game's material/texture-pack override path without changing the native player Omega marker.
