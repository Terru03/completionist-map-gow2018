## Important causal findings

### HUD crash

`goCompletionistRavenHUD` physically existed in `r_ui.wad` but was missing from `WAD_R_UI.GOPool`. Registering it eliminated the crash and allowed the custom HUD resource to instantiate.

### Single-target semantics

The stock class list does not include `CompletionistRaven`. Raven-origin add/remove therefore must query the live `CompletionistRaven` manager state directly. Stock-origin actions remain delegated to the game's normal behavior. This preserves the native one-target invariant and Replace in Compass semantics.

### Floating in-world marker

A dedicated type-`0x129` clone of `COMPASS_INWORLD_DOCK` is valid. The custom carrier initially produced no marker when `goCompletionistRavenHUD` had GOPool capacity 1. A stock-art A/B proved the new carrier itself resolved correctly. Raising only the Raven HUD GOPool capacity from 1 to 2 made the custom Raven render simultaneously on the compass and in-world.

Therefore a visual root shared by compass HUD and floating in-world rendering must provide at least two simultaneous instances.

## Production handoff

The production branch adds two read-only/local-state tools:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\tools\v0.10.4\verify-raven-production-state.ps1"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\tools\v0.10.4\adopt-raven-production-state.ps1"
```

The verifier fails closed unless the complete proven state is present. The adopter writes only an ignored local manifest under `build/`; it does not rewrite the game.

Canonical family data lives in `data/native-markers/raven.json` and follows `data/native-markers/schema.json`.

## Rule for the next collectible family

Do not regress Raven while adding another family. Every native Completionist family must preserve the same runtime invariants:

1. dedicated native compass class;
2. dedicated map visual;
3. dedicated HUD visual registered in GOPool;
4. HUD pool capacity sufficient for simultaneous HUD + in-world use;
5. dedicated type-`0x129` in-world carrier;
6. native mapcoords/compassgraph routing;
7. one active user target with stock Replace/Remove semantics;
8. completion lifecycle removes/suppresses the marker without synthetic progression writes.

The next family should be implemented from the marker schema, not by copying temporary Raven A/B controls blindly.
