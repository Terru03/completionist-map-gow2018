# Collectible locations with stock blue quest markers

The installed location overlay exposes 410 locations across 11 family filters.
It combines the existing Artefact, Lore Marker, and Legendary Chest catalogue
with an extraction of fixed chest, shrine, rift, scroll, and treasure placements
from the native game WADs. Every family has its own filter and selection title.
All these pins use the game's blue side-quest artwork and native `SIDE` targeting.

This implements the requested location-first view. New pins include already
collected objects; they do not claim to be remaining collectibles. Existing
Raven and Nornir completion handling continues unchanged. No save, quest,
counter, or gameplay state is written.

The 53 Raven and 88 Nornir marker definitions remain present, for 551 collectible
definitions overall. Nornir puzzle children still follow their existing
locked-chest attempt and broken-seal visibility rules. Three authored Niflheim
rift IDs are reused; 407 marker/coordinate rows are added. The location layer
owns those three icons in normal map mode to avoid native duplicate rendering.
Fast-travel enumeration retains them and the game's native filtering.

The 37 legendary chests include four fixed placements whose regional accounting is
unresolved. The 27 positively identified repeatable trial rewards are excluded.
The extra extraction excludes procedural/repeatable Niflheim and Muspelheim
chest templates, an unplaced prefab, buried loot that shares a chest resource,
and the realm-tear geometry for the already native Valkyrie Queen encounter.
No locations are invented to match completion counters. The 13 shrine locations
include two Tyr story-context placements; they do not assert 13 quest objectives.

The Niflheim lore row uses the catalogue's realm alias for its Summary binding.
The overlay places it under `NiflheimMain`, verified as the sole native map region
in that realm. This map-only override does not change its progression identity.

The additional catalogue records the source WAD hash, exact native record path,
world transform, and region for each placement. Shared/nested chest prefabs and
the two level versions of Thamur's shrine are deduplicated. Treasure map pickups
and dig sites pair by all 12 exact native quest identities. This covers the
fixed placements found by these extractors; it is not a claim that every loose
loot object or dynamically spawned reward in the game has a marker.

## Behaviour

- All and Completionist show the new locations in the current realm.
- Family filters show only that family and are offered only in realms containing it.
- Filter names and the existing scrolling filter-button window remain native.
- Realm changes retain the selected category when it exists in the destination.
- Fast-travel maps omit the custom locations and preserve native gateway handling.
- Selecting a pin shows its family name and identifies it as a location that may
  already be collected.
- Add, Replace, and Remove use native `SIDE` compass routing. Raven and Nornir
  target ownership is released before adding a location target.
- Custom artwork remains deferred.

## Crash recovery and reversibility

The first 410-location installation exceeded the engine's fixed marker-radius
registry. The startup dump stopped at `GoW.exe+0x8B0FE8` with all 732 entries
occupied and `dictionary is full, cannot add another item` in the loader log.
This package needs 922 unique joined map IDs. Its separate coordinate registry
has room for 2,926 entries and contains 953.

The subsequent locally modified package failed while opening the map at
`GoW.exe+0x4EF377`, dereferencing a null icon instance. It requested 340 Dock
markers while its restored UI pool contained only 40 Dock instances. Its stock
resource files and older map Lua also no longer matched the Raven/Nornir base.

`native/collectible-marker-capacity` expands the marker-radius registry to 2,048
slots. It verifies the exact executable hash and constructor instructions,
allocates storage near the executable, and changes only the constructor's table
pointer and two capacity operands. The empty header is updated as well. No
assertion is disabled, no unrelated allocator is replaced, and the executable
on disk stays unchanged. A companion copy of the pinned Raven/Nornir bridge
retains the original snapshot API and all 20 DXGI exports.

The first live recovery passed startup but exposed a separate map-query array
overflow: 653 entity pointers were written into the 512-slot array at
`0x22C3D00`. The loop failed at entry 512 (`0x541973`) after adjacent globals
corrupted those overflow entries. The replacement redirects all seven native
references, including the insertion site, to 4,096 zeroed slots before the array
is populated. Engine queries, object removal, and the original count are kept.
The complete executable reference scan found those seven array references;
no assertion or cookie check is suppressed. The marker-only recovery
`5cfb3a85946b4d05b7aa479ce724bb25` is rolled back and rejected by the installer.

The next map-open failure at `GoW.exe+0x184C48` was a separate UI physics pool
exhaustion (`!m_poolId.empty()`), reproduced in the 20:05 and 20:38 dumps. The
latest dump's saved RSI matches world index 7 in the native world table at
`0x22AE7E0`. That world uses the hardcoded 500-body/500-shape defaults in the
world constructor, regardless of the number of UI icon instances available.

The shim now redirects the size-calculation call at `0x543E4E` through a leaf
trampoline. For world 7 only, it sets both capacities to 2,048 before calling
the original sizing routine at `0x5EB250`. The engine then allocates and
initializes all dependent pools using those parameters. Worlds 0–6 retain
their existing parameters. The patch verifies the original call bytes and
requires the world table to be uninitialized; pool assertions remain active.

The recovery installer composes eleven targets:

- `mapmaster.dcb`, `mapcoords.dcb`, `wad_r_ui.dcb`, and map Lua provide the
  locations and filters. The user's current pool expansion preserves all 389
  baseline rows and adds 2,048 blue quest, 32 Raven, 32 Dock, 32 Fast Travel,
  and 16 Fight instances. The physics fix preserves that resource package.
- `r_ui.wad`, `wad_r_perm.dcb`, `compassgraph.dcb`, and boot options restore the
  matching Raven/Nornir resources from verified local backups.
- `dxgi.dll`, its pinned companion in `mods/completionist-map/native/`, and the
  bridge ownership manifest provide the capacity change.

The data builder verifies exact inverse reconstruction of its three DCB inputs
and the prior map Lua. Building 410 locations with the original 732-slot limit
now fails explicitly. The recovery build supplies the expanded capacity.

Installation requires the game to be closed and verifies every source and
candidate hash. All locally modified files are backed up before replacement.
A partial failure restores those exact files; rollback also removes the owned
companion when it did not previously exist. Rollback is independent of rebuilt
candidates and refuses to overwrite later unrelated edits. The executable,
mod loader, runic-chest script, and standard-chest script are preserved.

## Build and install

Run in this checkout from Windows with Visual Studio 2022 C++ tools:

```powershell
cmake -S native/collectible-marker-capacity -B build/collectible-marker-capacity -G "Visual Studio 17 2022" -A x64
cmake --build build/collectible-marker-capacity --config Release --parallel
ctest --test-dir build/collectible-marker-capacity -C Release --output-on-failure
py -3.14 -B tools/v0.10.5/recover-collectible-locations.py build
py -3.14 -B tools/v0.10.5/test_collectible_locations.py -v
py -3.14 -B tools/v0.10.5/test_collectible_recovery.py -v
py -3.14 -B tools/v0.10.5/recover-collectible-locations.py install
```

The recovery build requires the pinned local v4 backups and original bridge;
it fails if those bytes are unavailable. It writes
`build/collectible-recovery/report.json` and
`build/collectible-recovery/candidate/game-root/`. The installer prints the
operation journal path. Use that exact path for verification or rollback:

```powershell
py -3.14 -B tools/v0.10.5/recover-collectible-locations.py verify --operation <operation.json>
py -3.14 -B tools/v0.10.5/recover-collectible-locations.py rollback --operation <operation.json>
```

Roll back this recovery before changing an older Nornir or bridge layer. Its
backups restore the user's modified pre-recovery package, including its crash
workarounds; they do not claim to restore a working installation. The earlier
410-location operation `18ec8719464d459da62eec716ea17564` and 125-location
operation `a41b4c2bdad8482a90d22b9d303d0708` are both rolled back.

## Validation on 2026-09-26

They cover complete Lua 5.1 compilation, native row/coordinate identity, every
realm and category, treasure pairing, shared-prefab deduplication, native rift
reuse, fast travel, selection cleanup, compass ownership, and code preservation.
Six recovery tests cover exact install/verify/rollback, partial-write recovery,
refusal to overwrite unrelated edits, and rejection of missing entity or UI
physics capacity fixes.
The native capacity test checks the three patch operands, unchanged surrounding
bytes, unsupported-layout rejection, registry state validation, and collision
handling across the old and new limits. It also checks all seven exact entity
array instructions, their new targets, and rejection of unexpected targets.
It also executes the generated physics trampoline with a sizing-function
stand-in, checking the complete parameter block and return value for world
indices 0–8. Only index 7 may change. Corrupt call instructions and unreachable
trampoline addresses are rejected before producing a patch.
