# v0.10.2 material / texpack route

Status: research + first diagnostic preparation

## Why this branch exists

v0.10.1 proved that the synthetic map marker GameObjects do not expose loose-image setters (`SetTexture`, `SetImage`, `SetSprite`, etc.) but do expose `SetMaterialSwap`.

The next rendering route is therefore the game's authored UI material / texture pipeline rather than another loose-PNG experiment.

## Relevant engine-side findings

The decompiled GoW Lua UI uses `GameObject:SetMaterialSwap(name)` extensively for icons and UI art. The exposed `ui/mpicon.lua` helper also provides:

```lua
mpicon.level.SetMaterialSwap(go, iconName, materialSwapName)
```

which forwards to `game.UI.SetMPIconMaterialSwap` when the engine function is available.

This means the remaining problem is not moving or selecting the synthetic marker. v0.9.x/v0.10.1 already solved those. The remaining problem is supplying a game-recognised material/texture to that marker without altering stock map icons.

## PC texture-pack route

The open-source GOWTool project has PC releases for God of War (2018). Release `v0.1.3-alpha` explicitly added DDS/GNF texture import and `.texpack` packing.

Its packing code uses the input DDS/GNF filename stem as the texture file hash. A filename containing `TX_..._<16 hex digits>` uses the trailing 16 hex digits as the replacement hash. This is suitable for building patch texpacks once the stock UI texture hash is known.

God of War PC texture mods are loaded from patch texpacks, commonly under:

```text
GodOfWar\exec\patch\pc_le\
```

with the texpack added to `exec\boot-options.json` under `patch-texpacks`.

## v0.10.2 milestones

### A. Locate the map UI texture container

Inventory the installed game's `.texpack` / `.wad` containers and identify likely map / UI / shell / HUD packs.

### B. Identify the DockPoint texture hash

Extract the likely UI texpack(s) with the 2018-PC GOWTool and locate the texture used by the native DockPoint map marker.

A temporary global DockPoint texture replacement is acceptable **only as a diagnostic** to prove that a custom Completionist image can reach the map renderer through a patch texpack.

### C. Avoid global DockPoint replacement

The final mod must not globally reskin native docks. After the texpack pipeline is proven, determine one of:

1. a material-swap variant available on the cloned marker but unused by stock map markers;
2. an MPIcon material slot that can be addressed only on the synthetic clone;
3. a safely duplicated/repurposed authored UI material definition;
4. a separate authored marker GameObject/material route.

### D. Family mapping

Only after per-marker material isolation is proven should the Raven / Nornir / artefact / lore / chest families be wired to their custom art.

## Hard invariant: Kratos marker

The native Kratos player marker remains the game's native Omega symbol.

Completionist Map may hide/show the native player marker but must never replace its texture, material, icon family or visual design.

`assets/icons/concepts/player_marker_concept_master.png` is reference-only and must not enter the runtime replacement pipeline.

## Safety

- Do not mutate collectible completion/progression state.
- Do not globally replace DockPoint art in a release build.
- Do not touch the native player/Omega texture or material.
- Keep all first texpack experiments reversible through `boot-options.json` and removable patch files.
