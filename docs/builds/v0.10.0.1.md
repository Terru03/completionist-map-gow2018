# v0.10.0.1 - private icon fetch hotfix

## Build

`Completionist-Map-v0.10.0.1-ICON-PIPELINE-FIX.zip`

## Why v0.10.0 failed

The first v0.10.0 installer attempted to fetch the concept PNG masters from the private `feat/completionist-icon-system` branch through the GitHub Contents/raw route and received `404 Not Found` for `assets/icons/concepts/raven_concept_master.png`.

The file was not missing. The private raw/Contents acquisition path was the failure.

## v0.10.0.1 fix

Each concept PNG is now pinned by immutable Git blob SHA and fetched through authenticated GitHub CLI access:

`gh api repos/Terru03/completionist-map-gow2018/git/blobs/<sha>`

The installer parses the blob JSON, base64-decodes the PNG and validates the PNG signature before continuing.

Pinned families:

- Raven
- Nornir Chest
- Nornir Seal
- Nornir Bell
- Nornir Mechanism
- Lore Marker
- Artefact
- Legendary Chest
- Remaining Collectible
- Player Marker

The installer still generates transparent 24/32/48/64 px production candidates under `mods/completionist-map/icons/generated/` and writes `manifest.json` with dimensions and SHA256 hashes.

## Rendering discovery retained

The v0.10.0 map/HUD capability probes remain unchanged:

- `ICON_CAPS`
- `ICON_BIND_ATTEMPT`
- `ICON_BIND_RESULT`
- `HUD_ICON_CAPS`

Raven/Nornir synthetic map GameObjects attempt direct loose-PNG binding only if the runtime exposes a plausible `SetTexture` / `SetImage` style method. The HUD carrier is capability-probed but not blindly mutated.

If no loose-PNG API exists, the current stable DockPoint/HUD proof visuals remain and the logs determine the next authored material/texture-pack integration route.
