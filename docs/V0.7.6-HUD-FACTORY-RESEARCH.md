# v0.7.6 HUD factory research

## Why this exists

The v0.7.5 native-compass surrogate path is abandoned. The user test crashed immediately after `game.Compass.ShowMarker()` returned successfully, before any `FindMarkersByIconClass` probe ran. `pcall` cannot protect against the later native C++ failure.

The last non-crashing map prototype already provides the useful part of the UX: a separate Raven marker, collision/snap behaviour, Raven reticle text, and Add/Remove-to-Compass state. The remaining blocker is rendering a genuine gameplay-HUD marker for an arbitrary world XYZ.

## What v0.7.6 does

v0.7.6 is deliberately non-visual on the HUD. It keeps the safe map interaction path and uses the actual local `lua_source` tree plus runtime MainHUD introspection to discover a HUD-native object factory/template instead of continuing to guess at renderer internals.

Install-time source scan inventories:

- HUD `util.GetUiObjByName(...)` targets
- `UI.*` calls used by shipped UI scripts
- GameObject creation/clone/child/parent/material/transform methods
- `engine.*` creation-related calls
- exact source contexts for `Clone`, `Create`, `Instantiate`, `AddChild`, `Unparent`, `SetParent`, `SetMaterialSwap`, and compass-marker calls

Runtime MainHUD inventory logs:

- every live MainHUD GameObject field
- GO name and world position
- exposed `Clone`, `Duplicate`, `Copy`, `CreateChild`, `Instantiate`, transform and parenting methods
- likely object-factory functions on `UI`, `game.UI`, `engine`, and `engine.GameObject`
- relevant `util` methods
- Raven bearing without moving any HUD artwork

## Safety boundary

v0.7.6 does **not** call:

- `game.Compass.ShowMarker()`
- `game.Compass.FindMarkersByIconClass()`
- `Map.ChangeMarkerState()`
- native marker coordinate mutation

It also does not transplant `Map.CreateMarkerIcon()` objects into the gameplay HUD.

## Success criterion

Identify one supported HUD-native creation or clone path, or one existing HUD-native icon template that can be safely duplicated and repositioned. The next build can then render a dedicated collectible indicator using the already-proven arbitrary XYZ bearing calculation.
